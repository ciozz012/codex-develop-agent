# 员工服务助手 · 首轮功能清单

**本轮已完成首轮规划。下一轮只设计「查找员工可读的手册依据」。三项功能的实现和业务验收均待执行。**

这是分会话开发演练。员工可以询问内部手册，答复应附上自己能打开的原文。资料不足时，员工可以明确要求起草工单，供自己核对。下面的身份、条款和金额都是演练数据。

## 功能清单

| 功能 | 依赖的输入 | 可以单独验收的结果 |
|---|---|---|
| 1. 查找员工可读的手册依据 | 员工问题、已验证的身份、文档阅读权限和手册版本 | 检索结果包含足以回答问题的可读片段和出处。只有受限条款含答案时，结果为“可读资料中依据不足”，也不会透露受限条款的标题或内容。可以直接检查返回的片段。 |
| 2. 根据依据答复员工 | 原问题，以及功能 1 返回的片段、出处或查询状态 | 给定一份固定的检索结果，员工能看到准确答案并按出处找到对应条款。给定空结果，答复指出尚无依据。给定查询故障，答复说明暂时查不到。三种情况都能单测。 |
| 3. 按员工要求起草工单 | 尚未解决的问题、已确认的事实、员工是否明确要求起草 | 给定“手册没说，请帮我起草工单”，员工能看到一份可核对、可修改的草稿，正式工单提交次数为零。只有“手册没说”这一句时，草稿数和提交次数均为零。 |

先做功能 1，因为下游答复的金额与引用都取决于员工查到了哪条依据。功能 2 可用固定的检索结果单独验收。功能 3 可用固定的未解问题和员工指令单独验收。

## 下一轮的起点

演练中沿用已有登录身份和文档阅读权限。甲、乙部门各有一份现行《差旅手册》，员工只可读本部门版本。两份手册的第 4 条分别写着“每晚上限 500 元”和“每晚上限 800 元”。

- **有依据。** 甲员工问“出差住一晚能报销多少？”预期检索结果含 500 元及甲版第 4 条，乙版片段不进入结果。
- **只有受限依据。** 换一组独立测试资料，甲版只写报销流程，乙版仍写 800 元。同一位甲员工问同一问题，预期返回依据不足，出处为空。

**待决问题。** 实际项目用什么入口取得可信的员工身份和文档可读范围？本次演练把这两项作为已给定的输入，可以据此完成设计。接入真实系统前需核实来源。
