# 用人工标注校准模型评分器

本轮固定待评答案，只检验评分器的一项判断，例如“客服答复是否完整、准确地表达了现行条款”。编号是否一致等可直接核对的字段交给程序。把需要理解语义的部分交给评分器，例如“寄出”和“送达”能否表达同一个业务承诺。

## 先让人把通过边界说清楚

每个样本保留用户问题、评分时能看到的权威依据及版本、待评答案。由熟悉业务的人先独立标注通过或不通过，并标明支持判断的条款和关键事实。对有争议的样本，保留分歧，核对业务口径后再定标签。尚无定论的列作待裁决。合成规则推导的预期可用于演练，正式报告应注明标签来源。

例如，条款规定“补卡申请获批后 3 个工作日内寄出，到达日期视承运方而定”。用户问“何时寄出，哪天能收到？”

| 待评答复 | 按该条款的预期判断 |
|---|---|
| “审批通过后，最迟第三个工作日发出。具体哪天到，要看承运方。” | 通过。起算点、寄出期限和到达日期的不确定性都正确。 |
| “请放心，审批通过后三个工作日内一定送达。” | 不通过。把寄出期限改成了到达承诺。 |
| “获批后 3 个工作日内寄出。” | 不通过。用户问了到达时间，这部分尚未答复。 |

选样时既要有“只改一个关键事实”的错例，也要有“只换说法、意思不变”的正例。将同一工单、同一原答复及其近似改写放在同一组，再按组划分调试集和封存验收集。见过结果并据此改过规则的样本归入调试集。[EvalGen 的人工校准研究](https://arxiv.org/abs/2404.12272) · [MT-Bench 的评分偏差研究](https://arxiv.org/abs/2306.05685)

## 让评分器盲判

下面是一段可按业务条款调整的评分说明。

> 依据所给条款核对待评答案。只有用户问到的事实都答全，且关键动作、起算点、单位和限定条件正确时才通过。接受等价措辞。新增无依据的承诺判不通过。若所给依据不足以裁决，返回“无法判定”。输出判定、对应条款和一句可核对的理由。

盲判时只提供任务说明、问题、条款和待评答案。人工标签与标注理由由验收端保存。固定评分模型、提示词版本、采样设置、输入字段和输出解析方式。用调试集查分歧、改规则。若模型给连续分数，也在调试集上按事先约定的标准选定通过分数线。冻结版本和分数线后才揭开封存集。如果据此再作调整，这批题转为调试材料，改用新的未见样本验收。

## 分开看两种误判

开跑前约定用途、可接受的错误和所需样本量。例如自动放行前，可对错误承诺设单独门槛。按样本号配对人工标签与评分结果，报告四格计数（双方都通过、错放、错拒、双方都不通过）。两个方向的误判各用自己的分母。

- **错放率**用人工判不通过、评分器却通过的数量，除以人工判不通过的样本数。
- **错拒率**用人工判通过、评分器却不通过的数量，除以人工判通过的样本数。

以上分母包含该人工类别中评分器弃判或输出无效的样本。把这些数量按类别另列，同时报告有有效二元判定的样本数／已裁决样本数，防止大量弃判掩盖问题。人工待裁决样本另报。某类分母为零时记“未覆盖”。有波动时用相同设置重复抽查边界样本，保留翻转的结果。

交接时列出误判样本、判定依据、封存样本覆盖范围和本次门槛结论。先核实是条款缺失、人工口径不清，还是评分器忽略了关键事实。门槛未定或某类样本太少时，给出能补足证据的下一步。校准结论只适用于这项判分任务和这个评分器版本。[Langfuse 的模型评分器文档](https://langfuse.com/docs/evaluation/evaluation-methods/llm-as-a-judge)
